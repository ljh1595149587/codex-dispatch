## 读取代码的方式（重要）

**不要整文件 dump。** 先用搜索定位，再按行号范围精准取段：

```powershell
# 定位
Select-String -Path src\*.{{ext}} -Pattern 'def some_function'
# 取段
Get-Content src\some_file.{{ext}} | Select-Object -Skip 120 -First 60
```

原因：shell 输出会整段进入你的上下文。一次 dump 上千行会迅速耗尽窗口，逼你进入压缩，反而丢失早期读到的关键细节。宁可多做几次窄查询。

同理：`git log` 用 `--oneline`，`git diff` 指定路径，不要无参数全量输出。

## 代码审查任务的固定格式

被要求审查代码时，**不要写散文报告**。每条发现一行，按严重度从高到低排：

```
| 严重度 | 文件:行 | 问题 | 触发条件 | 依据 |
|---|---|---|---|---|
| 高 | store.py:163 | flush 失败整批丢弃 | SQLite 写入抛异常时 | 调用方 164 行无条件 batch=[] |
```

- **严重度**只用 高/中/低。高 = 会导致数据错误或崩溃；中 = 边界条件下行为不符预期；低 = 可维护性
- **触发条件**必须是具体的输入或状态，不能写"某些情况下"。想不出具体触发条件的，说明你没验证，不要写进表
- **依据**是 `file:line` 加一句话。不要复述代码
- 表格之后只允许再写一节「我不确定的」，列出你怀疑但没能验证的点

**不要提**：风格偏好、命名、格式化、"建议加注释"、"可以考虑重构"。只报会出错的东西。

**宁可少报。** 一条经不起复核的发现，比漏报三条的代价大 —— 每条都会被逐条验，假阳性浪费的是双方时间。

## 本机环境（Windows / PowerShell 5.1）

- **`rg` 不可用** —— Codex 自带的 ripgrep 未就绪（`codex doctor` 报 "search command could not be verified"）。用 `Select-String` 代替。
- **含中文的 `.ps1` 必须存成带 BOM 的 UTF-8。** PS 5.1 读无 BOM 文件时按 GBK 解码，中文注释被拆成非法 token，报出的错误行号和内容**完全不对应源码**（实测：报"第 42 行 Unexpected token '}'"，而该行是空格）。改完用这条自检：
  ```powershell
  $e=$null; [System.Management.Automation.Language.Parser]::ParseFile($p,[ref]$null,[ref]$e); $e
  ```
  Python 文件不要加 BOM。
- **不要对原生 exe 用 `2>&1`。** PS 5.1 把每行 stderr 包成 `NativeCommandError`，叠加 `$ErrorActionPreference='Stop'` 后，一行无害提示就能终止整个脚本。要丢弃 stderr 就在 cmd 层写 `2>NUL`。
- **PowerShell 没有 `< file` 输入重定向**（`<` 是保留字符）。需要关掉 stdin 时用 `& cmd.exe /c '"prog" args <NUL'`。
- **你的沙箱里 `python` 可能不可用** —— 遇到这种情况**如实报告"未验证"即可**，不要反复换命令重试，派活方会在自己的环境里补验证。（这是沙箱内的限制；派活方的 PowerShell 里 `python` 是可用的。）
- 只读沙箱下 PowerShell 可能受限语言模式限制，某些命令会被拦。同样：报告说明，不要硬试。
